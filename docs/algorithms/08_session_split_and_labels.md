# 08. 为什么要按 Session 切分，而不是按 Clip 切分

## 这是一个非常关键的问题

很多项目在训练时会直接把所有 clip 打乱，然后随机切分训练集和测试集。

这样做在当前项目里非常危险，因为：

- 同一个 session 的相邻 clip 会非常相似
- 同一个目标轨迹切出来的样本会共享大量上下文

如果这些样本同时出现在训练和测试里，就会形成泄漏。

## 当前是怎么做的

现在项目会先按 `session` 建索引，再做 `train / val / test` 划分。

而且已经进一步升级为：

- **按类别分层的 session 划分**

这样做的目的，是尽量保证：

- `Bird`
- `RotaryDrone`
- `FixedWing`

都能进入不同的数据子集。

## 这样切分有什么好处

1. 验证结果更可信。
2. 测试结果更接近真实泛化能力。
3. 不会因为同一会话泄漏导致精度虚高。

## 但要注意一点

当前标签来自文件名，而不是人工逐帧标注，所以即使切分做对了，它依然是“弱监督数据集”。

也就是说：

- 切分方式是对的
- 但标签粒度仍然是粗的
