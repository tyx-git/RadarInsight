# 30. 如何设计一份正式的 clip 级标注规范文档

## 为什么一定要先写规范，再开始大规模标注

很多团队一开始做数据集时，最容易犯的错误是：

- 先找人开始标
- 一边标一边讨论标准
- 最后不同人各有各的理解

这样做的结果通常是：

- 标签不一致
- 后期复核成本很高
- 模型训练时边界越来越乱

所以对当前项目来说，如果你准备从弱标签升级到高质量数据集，最关键的第一步不是“多找几个人来标”，而是：

**先写一份正式的 clip 级标注规范。**

## 这份规范到底要解决什么问题

一份真正有用的标注规范，至少要回答清楚：

- 什么是一个标注单元
- 哪些类别允许标
- 各类别的定义是什么
- 不确定样本怎么处理
- 哪些情况必须进入复核
- 输出字段应该包含什么

## 当前项目最推荐的标注单元

当前项目最推荐的标注单元是：

- **一个 clip = 一个标注单元**

因为当前模型训练本来就是按 clip 读取样本。

## 推荐类别体系

建议至少包括：

- `Bird`
- `RotaryDrone`
- `FixedWing`
- `Other`
- `Unknown`

## 为什么要有 `Other` 和 `Unknown`

- `Other`：明确不是主类，但能确认是别的目标
- `Unknown`：证据不足，无法稳定判断

这比强行硬贴主类更健康。

## 规范里必须写清楚的几部分

### 1. 标注对象定义

例如：

- 标注对象为 `RD clip` 对应的一段时间窗口样本
- 每个 clip 对应唯一 `sample_id`

### 2. 类别定义

不能只写类别名，还要写“什么条件下允许标成这一类”。

### 3. 可判 / 不可判标准

出现以下情况时，优先标 `Unknown` 或进入复核：

- 目标太弱
- 干扰太重
- 多目标混杂
- 信息不足

### 4. 置信度规则

建议至少有：

- `high`
- `medium`
- `low`

### 5. 复核规则

建议明确：

- 哪些样本必须复核
- 谁来复核
- 分歧如何裁决

### 6. 输出字段规范

建议至少包含：

- `session_id`
- `sample_id`
- `track_id`
- `t0`
- `t1`
- `label_main`
- `confidence`
- `annotator`
- `reviewer`
- `review_status`
- `notes`

## 一个推荐的规范结构模板

```text
1. 目的与范围
2. 标注单元定义
3. 类别体系定义
4. 可判 / 不可判标准
5. 置信度规则
6. 复核与裁决规则
7. 输出字段规范
8. 示例与反例
9. 常见错误
```

## 当前最推荐的实际做法

1. 先写一版 clip 级标注规范
2. 先挑小批量 session 做试标
3. 根据试标反馈修改规范
4. 再进入正式批量标注


高质量标注不是“更认真地打标签”，而是先把规则写清楚，再按统一规则稳定地执行。
