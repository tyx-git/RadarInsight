# 03. 从 `DPL` 复数数据生成距离-多普勒谱图

## 这一步在整个项目里的位置

当前项目不会直接把 `RD.mat` 当成已经处理好的谱图来训练。

真实情况是：

- 文件目录名叫 `RD`
- 但内部核心字段是复数 `DPL`
- 当前按 TD 类复信号处理
- 再通过 FFT 生成真正用于训练的距离-多普勒谱图

所以这一层的作用是：

**把设备侧交接过来的复数时域/脉冲域数据，变成模型能理解的 RD 时空输入。**

## 当前默认主路径

当前默认主路径是：

**单尺度 `DPL -> RD`**

也就是说，当前项目在真实训练时走的是一条稳定、可复现、已验证有效的单尺度路线。

## 当前默认处理流程

在 `src/prodata/mat_session_builder.py` 中，当前默认流程可以理解为：

1. 读取 `DPL` 复数矩阵
2. 沿距离维做 FFT
3. 沿多普勒维做 FFT
4. 保留复数结果
5. 生成 RD 帧序列
6. 再切成 `rd_clips.h5`

当前默认多普勒窗口为：

- `32`

## 为什么这里要保留复数结果

如果在这一层就只取幅度，会太早丢掉相位相关信息。

而当前 RD 分支后面还要构造：

- `real`
- `imag`
- `log amplitude`
- `temporal difference`
- `background suppressed`
- `local contrast`

所以这里保留复数结果，是为了给后续数据集层留下更完整的可学习信息。

## 这一步输出了什么

处理完成后，标准 session 里最关键的两个 RD 文件是：

- `radar/rd/rd_data.h5`
- `radar/rd/rd_clips.h5`

其中：

- `rd_data.h5` 更像 session 级原始 RD 序列存档
- `rd_clips.h5` 更像真正喂给模型的 clip 级输入

## 为什么这一步很关键

很多初学者会把重点全部放在 CNN 模型上，但对这个项目来说，`DPL -> RD` 本身就是算法链的重要一环。

因为如果这一层处理错了，后面的模型再强也只能学到失真的谱图模式。

## 对应源码

- `src/prodata/mat_session_builder.py`
- `manage.py`

## 初学者最该记住的一句话

当前 RD 模型看到的不是现成图片，而是从真实 `DPL` 复数数据经过 FFT 处理后生成的距离-多普勒谱图序列。
