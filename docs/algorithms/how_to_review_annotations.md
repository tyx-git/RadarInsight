# 如何复核标注结果

## 为什么“标完”不等于数据集完成

在当前项目里，人工标注的价值不只是“给一个类别名”，而是尽量保证：

- 标签稳定
- 规则一致
- 难样本不会被随手标错
- 最终数据集对模型训练真的有帮助

所以，标注完成之后必须做复核。

一句话：

> 没有复核的数据集，通常不能算高质量数据集。

## 1. 复核到底在检查什么

复核不是重新从头标一遍，而是重点检查这些问题：

- 类别是否标对了
- 同类样本的标准是否一致
- 是否把不可判样本强行标成了某一类
- 是否遗漏了 `Unknown`、`needs_review`、`confidence` 之类的重要信息
- 当前样本是否值得进入最终训练集

## 2. 在当前项目里，哪些样本最该优先复核

不是所有样本都要同样用力。

最值得优先复核的是：

### 1）模型经常混淆的样本

例如：

- `FixedWing` 和 `RotaryDrone`
- `Bird` 和 `FixedWing`

这类样本最容易影响模型边界。

### 2）低置信度样本

如果标注时写了：

- `confidence = low`

那这些样本应优先复核。

### 3）弱可见样本

例如：

- 微动很弱
- 背景很强
- 目标结构不连续

### 4）类别分布少的样本

如果某类样本本来就少，那每一条都更值钱，也更应该认真复核。

## 3. 复核时到底怎么做

推荐顺序如下。

### 第一步：先看原标签

先知道它原来被标成什么。

### 第二步：看完整 clip

不要只看一帧。

因为当前项目很多判断依赖的是：

- 整段时间里的连续变化
- 微动是否稳定存在
- 轨迹和谱图是否一致

### 第三步：判断是否可判

先问：

- 我现在真的能稳定判断它吗？

如果不能，就不要为了“有标签”而硬标。

这时更合理的是：

- `Unknown`
- 或 `needs_review = yes`

### 第四步：检查标注规则是否一致

例如你要问自己：

- 这条样本和之前同类样本的标准一致吗？
- 如果换一个人来标，会不会标成别的类？

如果答案不稳，这条样本就应该进入争议或复议池。

### 第五步：决定处理结果

复核后，一条样本通常有 4 种去向：

- 保持原标签
- 修改标签
- 改成 `Unknown`
- 暂时剔除，不进入训练集

## 4. 当前项目里，什么样的样本不应该轻易进入训练集

高质量数据集的关键，不只是“加样本”，还包括“减坏样本”。

下面这些样本，要非常谨慎：

- 目标几乎看不见
- 背景强得盖住目标
- 轨迹和 RD 对不上
- 片段太短，信息不完整
- 多位标注者意见长期不一致

这些样本不是一定不能留，但至少不能未经审查就直接入训练集。

## 5. 什么叫“争议样本”

争议样本指的是：

- 两个人看了之后，给出不同结论
- 或者同一个人前后都不确定

这类样本很常见，也很正常。

在当前项目里，争议样本通常应该：

- 单独记录
- 进入复议池
- 最后再由更熟悉任务的人统一裁决

而不是谁先标完就听谁的。

## 6. 复核时最容易犯的错误

### 错误 1：只看一帧，不看整段 clip

这会漏掉时间变化信息。

### 错误 2：为了“别浪费样本”，把不可判样本硬塞进某一类

这会直接污染训练集。

### 错误 3：复核只改标签，不记录原因

后面回头看时，就不知道为什么改。

### 错误 4：争议样本没有单独管理

最后这些样本会混进训练集，影响模型边界。

## 7. 当前项目里，复核后应该记录哪些信息

建议至少记录：

- `sample_id`
- 原标签
- 复核后标签
- 是否需要进一步复议
- 复核人
- 复核时间
- 简短原因

这样以后你才能追溯：

- 这条数据为什么被修改
- 哪些规则最容易引发争议

## 8. 复核和模型训练有什么关系

关系非常大。

因为模型很多时候不是因为“不会学”，而是因为：

- 给它的边界样本本来就有问题
- 给它的难样本标签不一致
- 给它的弱样本强行标成了明确类别

所以复核做得好，会直接影响：

- 混淆矩阵
- `macro_f1`
- 类间边界是否稳定

尤其在当前项目这种真实雷达数据条件下，复核质量对模型上限影响很大。

## 9. 当前项目里，什么时候最该启动复核

如果你看到这些信号，建议优先做人工复核：

- 某个类别长期 `F1 = 0`
- 混淆矩阵长期是同一方向错分
- 某一类只要换 session 就表现大变
- 模型训练集很好，但测试集一塌糊涂

这通常说明：

- 不是模型结构完全不行
- 而是数据边界本身有问题

## 最后总结

在当前项目里，复核的作用不是“再看一遍”，而是：

- 把明显错误标签找出来
- 把规则不一致的问题找出来
- 把不可判样本从训练集中分离出来
- 真正提升数据集质量

一句话：

> 复核不是标注流程的附属步骤，而是把“有标签的数据”提升为“可训练的高质量数据集”的关键步骤。
