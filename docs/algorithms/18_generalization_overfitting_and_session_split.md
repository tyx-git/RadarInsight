# 18. 泛化、过拟合和 session 切分：为什么不能只看一次高分

## 什么叫泛化

泛化可以简单理解成：

**模型不是只会做对已经见过的数据，而是对没见过的新数据也能做对。**

这在真实环境里比“训练集分数高”更重要。

## 什么是过拟合

过拟合就是：

- 模型在训练集上表现很好
- 但到了验证集或测试集上明显变差

它往往意味着模型学到的不是稳定规律，而是训练样本里的偶然细节。

## 这个项目里最容易出现的泄漏是什么

当前数据是按 session 组织的。

如果把同一个 session 里的 clip 随机打散后分别放进训练集和测试集，就会产生很严重的问题：

- 训练集和测试集会共享同一会话的背景、噪声、采集条件
- 模型看上去像是“泛化很好”
- 实际上只是记住了同一会话里的模式

这就叫数据泄漏。

## 为什么当前必须按 session 切分

因为当前项目真正想验证的是：

- 模型对新会话是否仍然有效

而不是：

- 模型能不能在同一会话里把相似片段重复认出来

所以当前训练与评估强制按 session 切分，这是可信评估最关键的工程约束之一。

## 为什么还要做按类别分层的 session 切分

如果只按 session 随机切，有可能出现：

- 某一类在验证集里太少
- 某一类在测试集里几乎没有

这样评价就会很不稳。

按类别分层切分的作用是：

- 尽量保证 `Bird / RotaryDrone / FixedWing` 都出现在训练、验证和测试中
- 让指标更有解释力

## 为什么不能只看 Accuracy

因为总体准确率有时会掩盖类别之间的不平衡。

例如：

- 某一类样本很多
- 另一类样本很少

模型如果把大类识别得很好，总体 Accuracy 可能仍然很高，但小类其实学得很差。

所以当前项目还会关注：

- `macro_f1`
- `per_class`
- `confusion_matrix`

## 弱监督为什么会影响泛化判断

当前标签来自文件名，是 session 级弱监督。

这意味着：

- 它可以支撑当前阶段训练
- 但它不等于逐帧精确标注

所以对当前结果的理解应该是：

- 模型已经能从真实数据里学到稳定信号
- 但结果不能被误解为“已经在精标 benchmark 上验证完毕”

## 为什么当前不做“只针对弱监督标签的专属优化”

因为你当前强调的是：

- 鲁棒性
- 通用性

如果模型过度依赖某一种弱监督特性，它可能在当前数据上分数更高，但换一批真实数据就不稳了。

所以当前路线更强调：

- 通用的时空建模
- 通用的正则化与训练稳定性策略
- 更可信的评估切分方式
