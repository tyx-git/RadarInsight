# 34. Session、Track、Clip、Sample、Label 与训练参数到底分别是什么

## 为什么要把这些概念放在一起讲

很多初学者看这个项目时，不是先卡在模型结构，而是先卡在这些词：

- `session`
- `track`
- `clip`
- `sample`
- `label`
- `train / val / test split`
- `sequence_length`
- `rd_frames`
- `macro_f1`
- `checkpoint`

这些词分别属于：

- 数据组织层
- 数据切片层
- 训练输入层
- 监督层
- 训练控制层
- 评估层

如果你把它们混在一起，后面看代码、看配置、看训练结果时就会很模糊。

所以这篇文档的目标是：

> 用一篇文章，把“数据是怎么组织的、模型到底在读什么、训练到底在控制什么”讲清楚。

## 一句话先记住

在当前项目里，可以这样理解：

> 一个 **session** 里包含连续的 **track** 和 **RD** 数据；连续数据会被切成多个 **clip**；数据集类再把 clip 整理成训练用的 **sample**；而 **label** 告诉模型这条 sample 应该属于什么类别。

如果这句话你已经理解了，项目主线就已经通了一半。

---

## 第一部分：这些核心概念分别是什么

## 1. Session 是什么

### 最直白的定义

在这个项目里，**session 是一次完整、连续、同源的真实观测过程**。

你可以把它理解成：

- 同一次雷达采集得到的一整段数据
- 一对 `TR.mat` 和 `RD.mat / DPL` 文件处理后的结果
- 一组完整的轨迹、RD、标签和质检文件的容器

它不是单帧，不是单个 clip，也不是一条训练样本，而是最外层的数据组织单位。

### 在目录里长什么样

一个典型 session 最终会落成类似这样的结构：

```text
data/sessions/<session_id>/
├─ meta_session.json
├─ qc/
│  └─ qc_report.json
├─ radar/
│  ├─ track/
│  │  └─ track_data.csv
│  └─ rd/
│     ├─ rd_data.h5
│     ├─ rd_clips.h5
│     └─ rd_alignment_diagnostics.jsonl
└─ labels/
   ├─ labels_trackclip.jsonl
   └─ labels_matched.jsonl
```

所以 session 不是抽象概念，而是项目里的真实目录单位。

### 它在项目里的作用

session 在当前项目里至少承担 5 个角色：

- 数据组织单位
- 标签传播单位
- 切片来源单位
- 训练切分单位
- 排障分析单位

也就是说，session 是整个工程流程的基础单位。

## 2. Track 是什么

track 指的是**目标随时间变化的一条连续轨迹**。

它通常保存在：

- `radar/track/track_data.csv`

里面常见字段有：

- `t`
- `range_m`
- `azimuth_deg`
- `radial_speed_mps`
- `snr_db`
- `frame_id`
- `track_id`

一句话理解：

> track 讲的是“目标怎么移动”。

它更偏运动学和行为特征。

## 3. RD 是什么

RD 是 `Range-Doppler`，也就是距离-多普勒表示。

在当前项目里，它主要存在于：

- `radar/rd/rd_data.h5`
- `radar/rd/rd_clips.h5`

一句话理解：

> RD 讲的是“目标在距离-速度频谱里长什么样”。

它更偏微动、能量分布和谱结构。

## 4. Clip 是什么

clip 是从连续长序列里切出来的一小段时间窗。

为什么要切？

因为模型训练时不能总是直接吃完整长序列，所以要把连续数据切成长度更稳定、可比较、可训练的小片段。

当前项目里的 clip 通常是：

- 一段 track clip
- 或与它配套的一段 RD clip

比如一个 clip 可能对应：

- `t0 = 0s`
- `t1 = 8s`

一句话理解：

> clip 是“从连续大序列里切出来的一小段训练片段”。

## 5. Sample 是什么

sample 是模型真正拿来训练的一条样本。

在当前项目里，一条 sample 通常由这些部分组成：

- `track_features`
- `rd_features`
- `label`
- `sample_id`

这里一定要区分：

- clip 是数据切片结果
- sample 是训练输入对象

在当前项目里，两者大多数时候是一一对应的，所以你会觉得它们很像，但工程语义不同。

## 6. Label 是什么

label 就是类别答案。

当前项目里的主标签有：

- `Bird`
- `FixedWing`
- `RotaryDrone`

label 回答的问题是：

> 这条数据应该被模型学成哪一类？

它本身不是轨迹、不是频谱，而是监督信息。

## 第二部分：它们之间的关系是什么

## 1. 从大到小的层级关系

在当前项目里，这几个概念按层级大致是这样套起来的：

### 第一层：Session

最大的观测容器。

### 第二层：Track 和 RD

session 里最核心的两条主数据链：

- track：目标怎么动
- RD：目标在频谱里长什么样

### 第三层：Clip

从连续的 track / RD 中切出来的一小段时间窗。

### 第四层：Sample

clip 被数据集类整理后，变成真正送进模型的一条训练样本。

### 第五层：Label

附着在 sample 上的类别答案。

## 2. 为什么一个 session 会产生很多 sample

因为 session 是连续长观测，而模型训练更适合固定长度的小片段。

所以项目会：

- 先保留完整 session
- 再切出很多 clip
- 再把 clip 变成很多 sample

这也是为什么：

- session 数量通常不多
- sample 数量通常很多

所以你不能把 sample 数量直接理解成独立观测数量。

## 3. 为什么训练切分必须看 session，而不是看 sample

因为同一个 session 里切出来的 sample 高度相关：

- 时间相邻
- 背景相近
- 目标相近
- 频谱结构相近

如果把这些 sample 随机打散到 train 和 test：

- 测试集就会混入很多和训练集几乎同源的样本

这样得出的高精度，很多时候是“假提升”。

所以当前项目必须按 session 切分。

一句话：

> session 是泛化评估单位，sample 是训练读取单位。

这两个概念不能混用。

---

## 第三部分：这些概念在训练流程里怎么串起来

当前项目的数据与训练链路可以理解成：

```text
TR.mat / RD.mat(DPL)
    -> prepare-pro
    -> 生成 session 目录
    -> session 内保存 track / RD / labels
    -> 从 session 切出 clip
    -> Dataset 读取 clip 形成 sample
    -> sample 进入模型训练
    -> label 用于监督学习
```

也就是说：

- session 是来源
- clip 是中间切片
- sample 是模型输入
- label 是监督答案

## 第四部分：训练过程中最常见的参数到底是什么意思

这一部分很重要，因为很多“专业名词”其实就是训练配置项。

## 1. `batch_size`

表示一次前向/反向传播中，同时喂给模型多少条 sample。

例如：

- `batch_size = 4`

意思是模型每一步同时处理 `4` 条样本。

### 它的影响

- 大一点：更快，但更吃资源
- 小一点：更省资源，但训练波动可能更大

## 2. `epochs`

表示模型把训练集完整看多少轮。

例如：

- `epochs = 5`

表示完整训练 `5` 轮。

### 它的影响

- 太少：模型可能还没学到东西
- 太多：可能开始过拟合

## 3. `learning_rate`

学习率表示参数更新步长。

一句话：

> 每次改模型参数时，改多大。

太大容易震荡，太小又学得太慢。

## 4. `weight_decay`

这是常见的正则化参数。

它的作用是：

- 不让参数无限增大
- 提高一定的泛化稳定性

## 5. `sequence_length`

这是轨迹分支最关键的参数之一。

它表示：

- 每条轨迹样本最终被整理成多少个时间步

例如：

- `sequence_length = 16`

表示每个轨迹 sample 最终是 `16` 个时间步的序列。

## 6. `rd_frames`

表示每个 RD sample 最终保留多少帧时间序列。

一句话：

> 模型在 RD 侧一次看多长的短时谱演化过程。

## 7. `rd_height` / `rd_width`

表示 RD 输入的空间尺寸。

例如：

- `rd_height = 64`
- `rd_width = 64`

表示每帧 RD 图最终会整理成 `64 x 64`。

## 8. `rd_input_channels`

表示 RD 输入共有多少个通道。

你可以把它理解成：

> 模型一次能看到多少种不同视角的 RD 特征。

当前项目里，它已经不再是单通道，而是多通道双视角表示。

## 9. `val_ratio` / `test_ratio`

表示：

- 多少 session 用作验证集
- 多少 session 用作测试集

注意：它们是按 **session** 切，不是按 sample 切。

## 10. `track_aux_loss_weight` / `rd_aux_loss_weight`

这两个参数表示：

- 轨迹辅助头对总损失影响多大
- RD 辅助头对总损失影响多大

一句话理解：

> 除了最终融合结果，训练时还会要求单独的轨迹分支和 RD 分支也尽量学对。

## 11. `label_smoothing`

这是训练分类器时常见的稳定化技巧。

作用是：

- 不让模型对训练标签过度自信
- 略微提高泛化稳定性

## 12. `macro_f1`

这不是训练参数，但训练和评估里经常出现，所以必须讲清楚。

### 它是什么意思

- 对每个类别分别算 `F1`
- 再把各类 `F1` 平均起来

### 为什么重要

因为它不会让一个强类把整体结果“抬得很好看”。

如果某个类别完全塌缩：

- `accuracy` 可能还勉强能看
- 但 `macro_f1` 通常会明显下降

## 13. `confusion_matrix`

混淆矩阵表示：

- 真实类别是什么
- 模型预测成了什么

它最适合判断：

- 哪些类经常互相混淆
- 当前模型到底是整体一般，还是某一类整类塌缩

## 14. `checkpoint`

checkpoint 就是训练过程中保存下来的模型权重文件。

当前项目里最常见的是：

- `best_fusion_model.pt`

它通常表示：

- 当前训练过程中，验证表现最好的那一版模型

## 15. `train / val / test`

这三个词一定要分清：

- `train`：用来学习参数
- `val`：训练过程中用来调模型、选最佳 checkpoint
- `test`：最后做独立评估，不参与训练调参

在当前项目里，这三者都是按 session 切分出来的。

## 第五部分：一些常见专业名词是什么意思

## 1. 弱监督（Weak Supervision）

当前项目很多标签来自文件名，因此属于弱监督。

意思是：

- 有标签
- 但标签不够细
- 不一定每一帧、每个 clip 都是人工精标

## 2. 泛化（Generalization）

泛化就是：

- 模型在没见过的新 session 上，仍然能表现稳定

不是训练集上变好，而是真正在新数据上变好。

## 3. 过拟合（Overfitting）

过拟合就是：

- 对训练集越来越会记
- 对验证集、测试集却不一定更好

## 4. ROI（Region of Interest）

ROI 就是“感兴趣区域”。

在当前项目里，通常指：

- 围绕目标位置裁出来的 RD 局部区域

## 5. 对齐（Alignment）

对齐指的是：

- 让轨迹预测的位置和 RD 中的目标位置尽量匹配

如果对齐不准，后面再强的 CNN 也会学偏。

## 6. 双视角 RD

指的是当前项目里 RD 不是只看局部裁剪，而是同时看：

- 局部 ROI
- 全局上下文

## 7. 符号不变性（Sign Invariance）

指的是：

- 模型不能只因为目标是接近还是远离，就把类别学错

所以当前项目加入了：

- 绝对速度特征
- 多普勒对称特征

来降低对速度正负号的过度依赖。

---

## 第六部分：以后你该怎么用这些概念排查问题

如果你怀疑：

- 数据组织有问题：先看 **session**
- 目标运动特征有问题：先看 **track**
- 切片不对：先看 **clip**
- 模型输入异常：先看 **sample**
- 类别来源不准：先看 **label**

如果你怀疑训练结果虚高，第一件事就是看：

- 是不是按 **session** 切分的

---

## 最后总结

把这篇文档浓缩成几句话，就是：

- `session`：最大的观测容器
- `track`：目标怎么移动
- `RD`：目标在距离-多普勒谱里长什么样
- `clip`：从连续序列切出来的小片段
- `sample`：模型真正读取的一条训练输入
- `label`：这条输入的类别答案

而训练参数决定的是：

- 一次喂多少 sample
- 一共训练多少轮
- 轨迹和 RD 输入有多长、多大、多复杂
- 训练和评估怎么切分、怎么稳定、怎么选最优模型

只要这几个层级你分清了，当前项目的大部分数据流、训练流和评估流就都会变得清晰很多。
