# 29. 如何把 RD clip 导出成适合 CVAT 标注的图片序列或短视频

## 先回答一个最实际的问题

你现在如果想在 `CVAT` 里标当前项目的数据，不能直接把这些文件丢进去：

- `.mat`
- `.h5`
- `rd_clips.h5`

因为 `CVAT` 更适合接收：

- 图像序列
- 视频文件

所以正确思路不是“让 CVAT 直接读雷达原始文件”，而是：

- 先把 `RD clip` 导出成可视化结果
- 再把这些可视化结果送进 `CVAT`

## 当前仓库里已经有什么基础

当前仓库已经有一个基础脚本：

- `tools/visualize_clips.py`

它目前可以：

- 读取 `radar/rd/rd_clips.h5`
- 取 clip 的中间帧
- 输出预览图到当前 session 的 `qc/` 目录

这说明仓库已经具备基础可视化能力，但还没有完整做成“批量导出给 CVAT 标注”的正式工具链。

## 对当前项目来说，更推荐导出什么

### 如果目标是 clip 级分类标注

更推荐：

- 导出短视频

因为 clip 级分类更关心“这一小段整体像什么”。

### 如果目标是帧级检查或更细粒度标注

更推荐：

- 导出图片序列

因为图片序列更容易逐帧核查。

## 一个推荐的导出目录结构

```text
exports/cvat/
├─ session_001/
│  ├─ clip_0001/
│  │  ├─ frame_000.png
│  │  ├─ frame_001.png
│  │  └─ ...
│  └─ manifest.json
└─ session_002/
   └─ ...
```

如果导出视频，也可以按 session 存成一组 `clip_XXXX.mp4`，并配一个 `manifest.json`。

## 为什么建议再加一个 `manifest.json`

因为单独只有图片或视频还不够，你还需要保留它和项目内部样本的对应关系，例如：

- `session_id`
- `sample_id`
- `track_id`
- `t0`
- `t1`
- 原始 `rd_clips.h5` 中的 key

这样标完之后，才能更容易回写回项目自己的标签体系。

## 最推荐的实操路线

```text
rd_clips.h5
-> 批量导出 clip 视频或图像序列
-> 附带 manifest.json
-> 导入 CVAT
-> 做 clip 级分类标注
-> 再回写成项目自己的标签文件
```


想把当前项目数据送进 CVAT，关键不是直接读 `.mat` 或 `.h5`，而是先把 RD clip 导出成一致、可追踪、可回写的可视化样本。
