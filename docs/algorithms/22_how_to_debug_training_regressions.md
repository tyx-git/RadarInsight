# 22. 如何定位训练效果下降：一个面向初学者的排障思路

## 先别急着怀疑模型结构

很多人看到训练指标下降，第一反应是：

- 模型是不是太弱了
- 要不要换更大的网络

但在真实项目里，训练退化更常见的原因其实是：

- 数据变了
- 切分变了
- 输入通道变了
- 损失权重变了
- 学习率变了

所以排查训练退化时，最重要的不是立刻改模型，而是先定位到底是哪一层变量变了。

## 推荐排查顺序

```text
数据是否一致
-> session 切分是否一致
-> RD 输入通道是否一致
-> 损失权重是否一致
-> 学习率和调度器是否一致
-> 混淆矩阵哪里变差了
```

## 第一步：先看是不是同一批数据

先确认：

- `data/sessions/` 是否重新生成过
- session 数量是否变化了
- 类别覆盖是否变化了
- clip 总数是否变化了

只要数据根目录变了，结果就可能完全不是同一个实验。

## 第二步：看 session 切分是否相同

当前项目按 `session` 切分 `train / val / test`。所以你一定要看：

- `training_session_manifest.json`

如果这里的 session 变了，那么结果变化并不一定代表模型退化。

## 第三步：看输入通道是否变了

在当前项目里，RD 输入通道变化会显著影响结果。需要确认：

- 当前 `rd_input_channels` 是多少
- 数据集到底选了哪几路通道

## 第四步：看损失权重是否变了

当前训练不是只有主损失，还有：

- `track_aux_loss_weight`
- `rd_aux_loss_weight`

如果这两个权重改了，训练曲线和最终效果都会明显变化。

## 第五步：看训练曲线，不要只看最终分数

你需要区分几种情况：

### 训练集和验证集一起差

更像是：

- 模型没学起来
- 学习率不合适
- 输入信息不够

### 训练集很好，验证集很差

更像是：

- 过拟合
- 泛化不足
- 验证切分更难了

### 前几轮差，后面慢慢上来

更像是：

- 训练只是收敛慢
- 不能太早下结论

## 第六步：看混淆矩阵，而不是只看 Accuracy

Accuracy 只能告诉你“总体对了多少”，但混淆矩阵会告诉你：

- 是哪一类开始坏了
- 哪两类更容易互相混淆

这比只看一个总分更有诊断价值。

## 第七步：把变量一次只改一个

错误做法是一次改很多东西，然后发现结果变了却不知道是谁造成的。

正确做法是：

- 一次只改一个核心变量
- 保留相同的数据和切分
- 再比较结果
