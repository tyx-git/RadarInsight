# 当前最优校准模型是如何完成校准的
## 为什么要写这篇文档
当前项目里，`202603252213-5-4-cpu-calibrated` 不是通过重新训练得到的新模型，而是在已有最佳 checkpoint 基础上，通过“组内校准”进一步提升出来的版本。很多初学者会疑惑：为什么不重新训练？为什么只改几个分数偏置就能提升结果？这篇文档的目标，就是把这次校准过程完整讲清楚。
## 先说结论
这次校准的本质不是改主干网络，也不是再训练一个新模型，而是：先用验证集观察当前模型在哪些类别边界上还存在系统性偏置，再为这些类别的最终 `logits` 加上一组更合理的偏置值，让模型在最终决策时更平衡。简单说，它是在“保持特征不变”的前提下，修正最终分类边界。
## 为什么当前模型还需要校准
在校准之前，主干网络已经把大方向学得很好了。`Bird` 基本已经稳定分开，真正剩下的错误，主要发生在同一粗类内部，也就是 `FixedWing` 和 `RotaryDrone` 之间。换句话说，这时候问题已经不再是“模型不会提特征”，而更像是“模型的最后决策阈值还有一点偏”。如果遇到这种情况，直接重训并不一定是成本最低、风险最小的做法，先做轻量校准反而更合理。
## 校准用的输入是什么
校准的输入 checkpoint 是 `artifacts/202603252213-5-4-cpu/best_fusion_model.pt`。校准时不会随便选一批数据，而是读取原训练产物中的 `training_session_manifest.json`，只使用当时训练时就已经划分好的验证集 `val_sessions`。这样做的目的是保证校准和原训练完全使用同一套验证标准，而不是临时换数据做“看起来更好”的调整。
## 第一步：重建和训练时一致的数据与模型
校准脚本会先根据 checkpoint 里的配置，重新构建 `RadarFusionDataset` 和 `FusionRadarClassifier`。它还会把训练时保存下来的归一化统计重新加载进数据集，例如轨迹特征中心值、轨迹特征尺度、全局轨迹摘要的归一化统计等。这样做很关键，因为校准必须建立在和原训练完全一致的输入分布上，否则最后学到的 bias 可能没有意义。
## 第二步：建立粗类映射
当前项目不是直接把每个类别都当成完全平级的类来处理，而是有一个粗类层。当前粗类映射可以理解为：`Bird -> BiologicalTarget`，`FixedWing -> AircraftTarget`，`RotaryDrone -> AircraftTarget`。这意味着 `FixedWing` 和 `RotaryDrone` 被认为属于同一个更大的粗类，而 `Bird` 在另一个粗类。校准时正是利用了这个结构，只对同一个粗类内部做细边界修正，而不是对所有类别做全局乱调。
## 第三步：收集验证集上的 logits
校准不会直接看最终预测标签，而是先让模型跑一遍验证集，收集每个样本对每个类别的原始 `logits`。你可以把 `logits` 理解成模型对各类的“原始打分”。这个阶段模型不更新参数，只是把它对验证集样本的内部判断结果全部记录下来，作为后续搜索最佳偏置的基础。
## 第四步：在粗类内部搜索最优偏置
真正的核心步骤，是在同一粗类内部搜索一组最优的 `logit bias`。算法做法并不复杂，但很有效：它先从零偏置开始，然后对同一粗类中的每个类别，尝试增加或减少一小段偏移量；与此同时，为了不破坏同组总平衡，它会把这个变化量按比例从组内其他类别上减回去。比如当前粗类 `AircraftTarget` 里只有 `FixedWing` 和 `RotaryDrone`，那么给 `FixedWing` 加一点 bias，实际上就等于同时给 `RotaryDrone` 减一点 bias，反之亦然。这个过程会在一组候选值上搜索，最终选择能让验证集 `macro_f1` 最好的那组偏置。
## 为什么优化目标是 `macro_f1`
这一步不是用 `accuracy` 当唯一标准，而是用验证集上的 `macro_f1` 来判断哪组 bias 更好。原因很简单：`accuracy` 很容易被容易分类的大类“拉高”，但 `macro_f1` 会平均看待每个类别，更能真实反映类别之间是不是平衡。对于当前项目这种仍然存在组内混淆的任务，`macro_f1` 比单纯的 `accuracy` 更适合作为校准目标。
## 这次实际学到了什么 bias
这次校准最终学到的 bias 保存在 `artifacts/calibrated/202603252213-5-4-cpu-calibrated/calibration_report.json`。具体数值是：`Bird = 0.0`，`FixedWing = -0.9`，`RotaryDrone = +0.9`。这意味着校准阶段认为，当前模型在 `AircraftTarget` 这组内部，对 `FixedWing` 给分偏高了一些，对 `RotaryDrone` 给分偏低了一些，因此最后把 `FixedWing` logit 稍微压低，把 `RotaryDrone` logit 稍微抬高。
## 为什么这个 bias 看起来和直觉相反
很多人第一次看到这个结果会觉得奇怪：前面不是一直在强调 `FixedWing` 很难吗？为什么校准却给它减分？原因在于，校准看的不是“哪个类更难”，而是“当前这个最佳 checkpoint 的剩余错误偏向哪里”。在这个阶段，模型已经把 `FixedWing` 救回来了很多，残余问题反而变成了部分 `RotaryDrone` 被错判成 `FixedWing`。所以校准不是盲目扶弱，而是在修正当前最优模型还存在的边界偏置。
## 第五步：把 bias 写进新的 checkpoint
当校准算法在验证集上找到更优 bias 后，它不会只打印一段日志，而是把这组 bias 真正写进一个新的 checkpoint。也就是说，`artifacts/calibrated/202603252213-5-4-cpu-calibrated/best_fusion_model.pt` 里不仅有原模型参数，也有这组 `logit_bias`。这样以后只要你评估这个校准版 checkpoint，评估脚本就会自动读取这组 bias，并在最终分类前把它加到 logits 上。
## 校准时评估到底是怎么生效的
评估阶段会先拿到模型输出的原始 logits，然后再执行“`logits + bias`”这个操作，最后再做 `argmax`。所以校准并不是改变模型前面提取特征的方式，而是在最后一步改“哪个类多加一点分，哪个类少加一点分”。这种方式的优点是极其轻量，尤其适合当前这种主干已经比较稳、但边界还有一点偏差的情况。
## 这次校准带来了什么提升
校准前，独立评估结果是：`Accuracy = 0.9301`、`Macro F1 = 0.8900`。校准后，独立评估结果提升到：`Accuracy = 0.9371`、`Macro F1 = 0.9012`。这说明校准不是只在验证集上“自嗨”，而是在真正独立评估时也带来了真实提升。更重要的是，这种提升没有破坏已经很稳的 `Bird`，而是在保持整体结构不变的前提下，把粗类内部的边界推得更合理了。
## 这次校准的优点是什么
第一，它不需要重新训练，成本低。第二，它几乎不动主干，不会破坏已经学好的表示。第三，它只在粗类内部做偏置修正，不会无意义地影响已经稳定的大类边界。第四，这种思路天然适合未来更大的类别体系：只要有粗类映射，就可以在粗类内部继续做类似校准。
## 这次校准的局限是什么
它毕竟是后处理校准，不是替代表示学习。如果前面的特征本身很差，校准救不了。它也不能替代更高质量的数据和更强的前端表示。你可以把它理解为“最后一公里调优”，而不是“从零到一的主能力来源”。所以当前项目的正确理解是：主干和特征链负责把模型学强，校准负责把最后的组内决策边界再摆正一点。
## 初学者应该怎么理解这次校准
如果你是初学者，最简单的理解方式是：模型已经学会了“看图”和“看轨迹”，也已经大致知道不同目标之间的区别，但在最后做选择时，还会有一点“偏心”。校准就是拿验证集当作一面镜子，看看模型偏向了谁，再给最后的类别打分加一点小修正，让决策更平衡。它不是重造一个新模型，而是把已经不错的模型调整得更准确一些。
## 一句话总结
`202603252213-5-4-cpu-calibrated` 之所以比原版更强，不是因为它重新训练出了新主干，而是因为它在原最佳 checkpoint 的基础上，利用验证集学习到一组更合理的组内 logit 偏置，并把这组偏置写进了新的 checkpoint，从而更好地修正了 `AircraftTarget` 内部的细分类边界。
