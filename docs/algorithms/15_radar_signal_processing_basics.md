# 15. 雷达信号处理基础：这个项目到底在处理什么物理量

## 先把雷达想简单一点

可以先把雷达理解成：

**主动发射电磁波，再接收目标反射回来的回波，并从回波里估计目标位置和运动状态。**

和摄像头不同，雷达不是直接“看见目标长什么样”，而是通过信号变化去反推：

- 目标离我多远
- 目标朝我靠近还是远离
- 目标回波强不强
- 目标的运动是不是稳定

## 当前项目最常用的几个物理量

### 距离 `Range`

距离本质上来自回波往返时间。

粗暴理解就是：

- 信号发出去
- 打到目标反射回来
- 用时间延迟换算成距离

在项目里，距离相关信息会体现在：

- `TR` 数据里的 `R_m`
- RD 谱图的距离轴

### 径向速度 `Radial Velocity`

径向速度是目标沿着雷达视线方向的速度。

注意：

- 它不是目标的真实三维速度大小
- 它只表示“朝向雷达”或“远离雷达”的那部分速度

在雷达里，径向速度通常通过多普勒效应估计。

在项目里，它会体现在：

- `TR` 数据里的 `V_m`
- RD 谱图的多普勒轴

### 方位 `Azimuth`

方位描述目标在水平面上的方向。

在项目里，它主要体现在轨迹分支中，因为轨迹分支会使用：

- `azimuth_deg`
- `delta_azimuth_deg`
- `turn_rate_degps`

### 信噪比 `SNR`

信噪比可以粗略理解成：

- 目标信号有多明显
- 噪声和杂波有多强

SNR 不是类别标签，但它会影响模型学习难度，因为低 SNR 目标往往更难识别。

## 什么是杂波 `Clutter`

杂波可以简单理解成：

- 不是我们想识别的目标
- 但它会出现在雷达回波里

例如地面、建筑、树木、环境反射，都会形成背景结构。

这也是为什么项目里要做：

- `background suppressed`
- `local contrast`

因为模型不仅要看到目标，还要学会不被背景误导。

## 为什么雷达信号处理和深度学习不能分开看

很多初学者会把“信号处理”和“深度学习”看成两件完全独立的事。

但在这个项目里，它们是串起来的：

- 如果前面的信号处理把目标结构破坏了，后面的网络再大也学不好
- 如果前面的信号处理保留了更多有效结构，后面的网络就更容易学到稳定模式

所以本项目的思路不是“信号处理结束后再让模型随便学”，而是：

- 先把真实雷达数据尽可能整理成对模型友好的表示
- 再让模型在这个基础上提取更深的时空特征

## 当前项目里雷达信息分成两条链

### 1. 轨迹链

来自 `TR`，主要反映：

- 距离变化
- 速度变化
- 方位变化
- 轨迹抖动

它更偏宏观行为建模。

### 2. RD 链

来自 `DPL -> RD`，主要反映：

- 微动结构
- 谐波模式
- 局部谱峰
- 时间上的持续变化

它更偏微动细节建模。

## 为什么一个项目要同时看轨迹和 RD

因为它们回答的是不同层面的问题。

例如：

- 轨迹告诉你目标“整体怎么动”
- RD 告诉你目标“局部怎么振动、怎么摆动、怎么出现谐波”

只看任何一边，都容易丢信息。

这就是当前项目采用双分支融合模型的根本原因。

## 对应到本项目的数据文件

当前你最应该建立的对应关系是：

- `TR.mat` -> 轨迹时序数据
- `RD.mat` 中的 `DPL` -> 复数雷达信号
- `DPL -> RD` -> 距离-多普勒谱图序列

再往后才是：

- `track_data.csv`
- `rd_clips.h5`
- 模型训练

## 对应源码

- `src/prodata/mat_session_builder.py`
- `src/training/dataset.py`

## 初学者最该记住的一句话

这个项目不是在“看图片”，而是在利用真实雷达回波中关于距离、速度和微动的信息做目标识别。
