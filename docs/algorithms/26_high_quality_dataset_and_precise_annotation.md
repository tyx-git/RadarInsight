# 26. 什么才算高质量数据集，以及你该如何做更精准标注

## 先说结论

高质量数据集不是“样本多”就够了，也不是“有人标了一遍”就够了。

对当前项目来说，一个真正高质量的数据集至少要同时满足：

- 标签正确
- 标签粒度合适
- 标注标准一致
- 类别覆盖合理
- 困难样本被保留
- 训练 / 验证 / 测试切分可信
- 有复核和质检机制

## 高质量数据集的 7 个核心标准

### 正确性

最基本的问题是：标签到底对不对。

### 一致性

不同标注员面对相同样本，是否会给出相同判断。

### 粒度合适

对当前项目而言，最推荐的目标粒度是：

- **clip 级标注**

### 覆盖充分

高质量数据集不能只包含最容易的样本，还应覆盖：

- 远距离样本
- 低 SNR 样本
- 杂波强样本
- 边界模糊样本
- 不同场景与时段样本

### 类别平衡

不要求绝对一样多，但不能严重失衡到让某些类几乎学不到。

### 可信切分

必须按 session 切分，而不是把同一 session 的 clip 打散进不同集合。

### 质检机制

必须回答：

- 谁标的
- 谁复核的
- 不确定样本怎么处理
- 有无二次裁决

## 什么叫“更精准标注”

对当前项目而言，更精准主要意味着四件事：

- 从 session 级走向 clip 级
- 明确“可判”和“不可判”
- 给出清晰的类别定义
- 加入人工复核

## 一个更实用的类别设计建议

如果你后面要把数据集做得更通用，建议类别体系至少考虑：

- `Bird`
- `RotaryDrone`
- `FixedWing`
- `Other`
- `Unknown`

## 你应该给每个标注样本补哪些信息

建议不仅标类别，还标这些附加信息：

- `label_main`
- `confidence`
- `visible_quality`
- `review_status`
- `annotator`
- `reviewer`
- `notes`

## 一个实际可执行的高质量路线

```text
session 级弱标签起步
-> clip 级人工精标
-> 不确定样本单独管理
-> 双人复核
-> 建立 QA 规则
-> 再扩大规模
```


高质量数据集的本质，不是样本越多越好，而是标签越准、规则越稳、复核越严越好。
