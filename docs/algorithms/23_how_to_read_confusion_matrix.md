# 23. 如何从混淆矩阵和分类指标反推模型短板

## 为什么混淆矩阵比一个总分更有用

很多初学者最先看的指标是：

- `accuracy`

它当然重要，但它只能告诉你“整体对了多少”，却很难告诉你：

- 哪一类识别差
- 哪两类容易混淆
- 当前模型到底短板在轨迹还是在微动

这时混淆矩阵就非常有用。

## 混淆矩阵怎么读

一张混淆矩阵里：

- 行通常表示真实类别
- 列通常表示预测类别

对角线越高，说明该类越容易被正确识别；非对角线越高，说明这两类越容易被混淆。

## 先看哪一块最重要

先看对角线。如果某一类的对角线明显低，就说明：

- 这类本身识别难
- 或者它和其他类的边界不清晰

再看这一行里最大的非对角元素，就能知道它主要被错分成谁。

## Precision、Recall、F1 怎么配合看

### Precision 高，Recall 低

说明模型比较保守：

- 一旦预测成这一类，往往是对的
- 但很多真正属于这一类的样本没有被抓住

### Recall 高，Precision 低

说明模型比较激进：

- 它很愿意预测成这一类
- 但容易把其他类也错判成这一类

### F1

F1 是 Precision 和 Recall 的折中结果。如果你只想先看一个更平衡的单类指标，F1 通常最方便。

## 如何从混淆矩阵反推“该优化哪里”

### 如果同一类总被错成另一类

优先怀疑：

- 两类边界特征不够清楚
- 输入表示不够区分

### 如果所有类都混得很厉害

优先怀疑：

- 数据处理有问题
- 标签有问题
- 训练根本没收敛

### 如果只有某一类持续偏差很大

优先怀疑：

- 该类样本规模较少
- 该类本身更难
- 当前输入对该类不够友好

## 推荐阅读顺序

```text
overall_metrics
-> confusion_matrix
-> per_class_metrics
-> training_curves
```

先看整体，再看错分细节，再回头看训练过程。

## 对应源码与产物

- `src/training/evaluator.py`
- `src/reporting/report_builder.py`
- `artifacts/<run>/evaluation_report.json`
- `reports/real/<run>/confusion_matrix.png`
- `reports/real/<run>/per_class_metrics.png`


混淆矩阵不是“好不好看”的图，而是理解模型短板最直接的诊断工具之一。
