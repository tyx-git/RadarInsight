# 20. 项目数据文件与格式基础：为什么这里会同时出现 CSV、JSONL、H5

## 为什么一个项目会有这么多文件格式

初学者很容易困惑：

- 为什么轨迹不是都放在一个大文件里？
- 为什么标签不用 CSV？
- 为什么 RD 要用 HDF5？

原因很简单：

**不同类型的数据，适合不同的存储格式。**

## `CSV` 适合什么

`CSV` 最适合表格型数据。

在本项目里：

- `track_data.csv`

非常适合用 `CSV`，因为轨迹本质上就是一行一行的时间序列表格。

例如一行里会有：

- 时间
- track_id
- 距离
- 方位
- 速度
- SNR

这种结构用 `CSV` 非常直观，也方便 pandas 读取。

## `JSONL` 适合什么

`JSONL` 就是：

- 每一行一个 JSON 对象

它非常适合存：

- 一条一条结构化记录
- 每条记录字段可能稍微复杂一点的数据

在本项目里：

- `labels_trackclip.jsonl`
- `labels_matched.jsonl`

都适合用 `JSONL`，因为每一条标签记录往往不仅有类别，还会有：

- session_id
- track_id
- 时间窗
- 路径信息

## `HDF5` 适合什么

`HDF5` 最适合存：

- 大体积数组
- 多维张量
- 需要高效随机读取的数据

在本项目里，RD 数据显然更适合 `HDF5`，因为它是：

- 多帧
- 多维
- 体积较大

所以当前用：

- `rd_data.h5`
- `rd_clips.h5`

来存储 RD 相关数组。

## 为什么 RD 不用 CSV

因为 RD 不是普通表格。

它本质上是：

- 帧序列
- 二维谱图
- 或者更高维张量

如果硬存成 CSV：

- 文件会非常大
- 读写很慢
- 结构也不清晰

## 为什么标签不用 HDF5

因为标签不是大数组，而是结构化记录。

用 `JSONL` 更好处在于：

- 人能直接看
- 调试方便
- 逐条读取也简单

## `meta_session.json` 有什么用

`meta_session.json` 更像一份摘要信息。

它会帮助你快速知道：

- 当前 session 是什么标签
- RD 形状是什么
- session 的基础元信息是什么

所以它不是训练主输入，但对调试和理解数据很有帮助。

## 为什么这些格式组合起来反而更合理

很多新手会本能觉得：

- “最好所有东西都统一成一种格式”

但在工程里，真正合理的是：

- 表格数据用表格格式
- 记录数据用记录格式
- 张量数据用数组格式

这样反而最清楚、最高效。

## 当前最关键的几类文件

如果你只记住最重要的几项，可以先记：

- `track_data.csv`：轨迹时序表
- `labels_trackclip.jsonl`：clip 级标签记录
- `labels_matched.jsonl`：匹配后的标签记录
- `rd_clips.h5`：模型真正读取的 RD clip 张量
- `meta_session.json`：session 摘要信息

## 初学者最该记住的一句话

项目里同时使用 `CSV + JSONL + HDF5` 不是混乱，而是针对不同数据类型做的合理工程选择。
