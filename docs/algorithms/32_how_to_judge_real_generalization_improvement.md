# 32. 如何判断一次训练是否真的提升了泛化能力

## 为什么这个问题非常重要

在这个项目里，单看一次训练的 `accuracy`，很容易得出错误结论。

原因很简单：

- 当前数据是 `session` 级弱监督，不是逐帧精标
- 不同 session 之间差异很大
- 某些类别很容易出现“整类塌缩”
- 一次训练里，训练集和验证集的表现可能完全不是同一个故事

所以，判断模型有没有真的进步，不能只看“这次数字是不是更高”，而要看：

> **模型是不是在新 session 上变得更稳、更平衡、更可重复。**

## 错误判断方式

先说几个最常见的误区。

### 误区 1：训练集精度升高，就是模型更强了

不是。

训练集精度高，只能说明模型更会拟合训练数据。它可能真的学到了规律，也可能只是更会记忆。

如果出现这种情况：

- `train_accuracy` 很高
- `val_macro_f1` 很低
- 测试集某一类完全为 `0`

那通常不叫提升，而叫**学偏了**。

### 误区 2：只看 `accuracy`

在当前项目里，`accuracy` 很重要，但**不够**。

因为如果模型把大部分样本都压到某一个容易识别的类别里，`accuracy` 可能还能看起来不差，但 `macro_f1` 会明显掉下去。

### 误区 3：只看一次 run 的结果

单次 run 可能会受：

- session 划分差异
- 初始化差异
- 某类样本在当前 split 中刚好更难或更容易

影响。

所以在这个项目里，**一次结果只能当参考，不能当定论**。

## 当前项目里，应该优先看哪些指标

### 1. `Macro F1`

这是当前最重要的指标之一。

原因是：

- 它会平均考虑每个类别的表现
- 不会让一个强类把整体结果“抬得很好看”

如果某次训练：

- `accuracy` 变高了
- 但 `macro_f1` 没涨，甚至下降了

那往往说明：

- 模型只是更偏向某些强类
- 并没有真正提升整体泛化

### 2. `per_class` 指标

当前项目一定要单独看每一类的：

- `precision`
- `recall`
- `f1`

为什么？

因为你当前最常见的问题不是“整体都差”，而是：

- 某个类别很好
- 某个类别直接塌成 `0`

如果你不看 `per_class`，很可能会误以为模型整体在变好。

### 3. 混淆矩阵

混淆矩阵是当前项目里最值得长期盯的东西之一。

你应该重点看：

- 是否还存在**整类对调**
- 误分类是不是有方向性
- 错分是在两类之间来回混，还是一边被另一边“吃掉”

例如：

- `FixedWing -> RotaryDrone`
- `RotaryDrone -> FixedWing`

如果长期这样，就说明模型并不是不会分类，而是**当前判别线索选错了**。

### 4. 训练曲线和验证曲线的关系

不是只看它们高低，而是看它们之间的关系。

#### 健康状态

- `train_loss` 下降
- `val_loss` 也下降或保持平稳
- `val_macro_f1` 逐步提升

这通常说明模型真的在学有泛化价值的东西。

#### 不健康状态

- `train_accuracy` 一直涨
- `val_macro_f1` 不涨，甚至下降

这通常说明模型在过拟合。

## 当前项目里，什么样的提升才算“真实提升”

对于当前仓库，我建议把“真实提升”定义成以下 4 条至少满足 3 条：

### 条件 1：`Macro F1` 提升

这说明不是只优化了强类，而是整体分类平衡性在变好。

### 条件 2：没有新增类别塌缩

如果某一版模型：

- 总体 `accuracy` 提升了
- 但某个类别 `F1` 直接变成 `0`

那通常不能算好升级。

### 条件 3：混淆矩阵里主要误分类方向变弱

比如之前总是：

- `FixedWing -> Bird`

这次数量明显减少了，那才说明模型真的在改进这条边界。

### 条件 4：独立评估结果和验证集趋势一致

训练时看到验证集变好，独立 `evaluate` 后测试集也变好，这才更可信。

如果：

- 验证集很好
- 但独立测试集不行

那说明提升可能只是“当前 split 上看起来更好”。

## 当前项目里，哪些信号说明“泛化正在变好”

### 好信号 1：Bird、FixedWing、RotaryDrone 三类都至少能被识别出来

只要有一类长期 `F1 = 0`，那泛化就还没过关。

### 好信号 2：错误开始从“整类塌缩”变成“边界样本混淆”

这点非常关键。

如果模型一开始是：

- 整个 `FixedWing` 全被判成别的类

后来变成：

- 只有一部分边界样本混淆

那通常说明模型确实在进步。

### 好信号 3：不同 run 的趋势越来越一致

真正的泛化提升，通常会让结果更稳定。

也就是说：

- 不同 run 之间数值可能有波动
- 但主趋势相似
- 不会一轮大好、一轮大崩

## 当前项目里，哪些信号说明“还没有真正提升”

### 坏信号 1：Bird 一直很好，其他类总在换着塌

这说明模型只是学会了最容易的一类，剩余边界还没建立起来。

### 坏信号 2：训练集越来越强，但测试集主要错误模式没变

比如你每轮训练都看到：

- `FixedWing -> Bird`

始终不变，那就说明主根因还没被碰到。

### 坏信号 3：loss 降了，但 `macro_f1` 不涨

这通常说明模型只是变得更自信，未必变得更正确。

## 当前项目的实用判断流程

每次你训练完一个 run，我建议按下面这个顺序判断：

### 第一步：先看测试集 `Macro F1`

如果没涨，先不要急着说模型变好了。

### 第二步：看 `per_class`

确认：

- 有没有类别 `F1 = 0`
- 哪一类在拖后腿

### 第三步：看混淆矩阵

判断主要错分流向有没有发生变化。

### 第四步：再看训练/验证曲线

确认这次结果是：

- 泛化变好
- 还是只是训练更会拟合了

### 第五步：最后再决定要不要保存 Git

只有在你确认：

- 整体指标更好
- 没有新增类别塌缩
- 主要错分方向有改善

这时再保存为新的里程碑，才更有意义。

## 一句话总结

在当前项目里，**真正的泛化提升**不是“某个数字变高”，而是：

- `Macro F1` 变高
- 混淆矩阵更健康
- 每一类都更平衡
- 不同 run 趋势更稳定

只要你以后都按这个标准判断，就不容易被表面上的“好看数字”带偏。
