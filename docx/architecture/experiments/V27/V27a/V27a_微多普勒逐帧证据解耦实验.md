## 2. 研究问题与假设

### 2.1 研究问题

V27 L2 已经接收 stable8，但当前路径为：

```text
逐事件 stable8 摘要
    -> 共享 Fusion
    -> Liquid V2
    -> classifier
```

V27a 要回答两个可分离的问题：

1. stable8 在脱离共享 Fusion、只作为独立 late residual 时，是否仍能
   提供安全的 DBB 边界修正？
2. 在相同独立 late-residual 结构下，可靠的逐帧 stable8 evidence 及其
   因果波动/事件间一致性，是否比事件级 stable8 摘要提供额外的 Bird/Drone
   判别信息？

### 2.2 预注册假设

- H1（解耦假设）：共享 Fusion 造成的耦合错误可以通过冻结基座、独立
  causal late residual 部分消除；stable8 的信息增益不应被解释为重新训练
  主干的收益。
- H2（保留时序假设）：逐帧可靠 stable8 的波动、持续性、事件内一致性和
  事件间结构比单一事件摘要保留更多可用于 Bird/Drone 边界的证据。
- H3（质量边界假设）：没有可靠微多普勒帧时，处理臂必须输出 exact-zero
  evidence intervention；不能把 `valid=True`（仅表示 RD 存在）当成可靠
  微多普勒观测。

H1/H2 是待证伪假设，不是预先承诺的性能结论。

### 2.3 因果解释边界

V27 epoch-11 的冻结 logits 已经包含“stable8 经共享 Fusion 进入 Liquid V2”
这一历史路径。V27a 的 late residual 只能在冻结输出上增加一个独立、可控的
校正路径；它可以检验该路径是否能恢复/修正错误，但不能单独证明共享 Fusion
内部的状态污染已经被完全移除。若要直接比较“训练时不输入 stable8”的主干，
需要另一个重新训练的 matched baseline，不能由本实验的结果推导。

## 3. 处理臂与唯一变量

### 3.1 Control：冻结基座

```text
logits_control = frozen V27 epoch-11 sequence_logits
```

不训练任何参数，不重新拟合 L3，不改变 V27 L1。

### 3.2 Mechanism control：独立 stable8 causal residual

```text
frozen V27 logits
  + reliable-event stable8 summary token
  -> common hierarchical causal evidence encoder
  -> constrained three-class late residual
```

该臂只用于检验“将 stable8 从共享 Fusion 中移到独立 late path”这一机制。
每个有可靠帧的事件只生成一个 stable8 summary token；无可靠帧的事件没有
evidence token。V19 的 zero-sum/bound 实现只能作为工程参考；不复用 V19
的 checkpoint、累计均值、loss 或 provenance，V27a 由自己的合同重新定义。

### 3.3 Main treatment：独立逐帧 evidence causal residual

```text
frozen V27 logits
  + reliable frame-level stable8 evidence
  -> independent causal frame/evidence encoder
  -> event representation
  -> causal parent aggregation
  -> constrained three-class late residual
```

主处理臂必须使用当前 V18 evidence cache 中已通过审计的逐帧信息。首轮只
使用 stable8 对应的 8 个 frame descriptor；181-bin residual Doppler profile、
64-bin envelope modulation profile 和完整 23 维 descriptor 保留为后续
独立消融，不得在首轮同时加入。

### 3.4 两个 treatment 的共同编码器

为了使“事件摘要 vs 逐帧证据”成为唯一主要变量，两臂使用完全相同的层级
结构、隐藏宽度和参数形状，只改变每个事件送入 frame encoder 的 token 数：

```text
token projection (8 -> H)
    -> frame GRU（每个 TR 事件开始时显式 reset）
    -> event representation
    -> parent/event GRU（只沿 TR 事件因果顺序更新）
    -> bias-free residual projection (H -> 3)
```

- Mechanism control：每个有可靠帧的事件送入一个 token，即 V18 stable8
  summary；frame GRU 仍调用一次。
- Main treatment：每个事件按 evidence cache 顺序送入所有可靠 frame token；
  frame GRU 只在该事件内更新，然后 reset，不能跨事件携带 frame state。
- 两臂的 parent/event GRU、residual projection、激活和 bound 完全相同；
  非最终 residual encoder 参数使用同一初始化规则，最终 residual projection
  全零初始化。两臂参数量必须逐项相等，不能用“容量匹配投影”事后解释差异。
- 该设计允许 Main 使用事件内顺序、持续性和波动，同时不让它获得额外的
  可训练层数或更大的参数容量。

## 4. 固定项与禁止项

以下项目在三臂间固定：

- V27 L2 epoch-11 checkpoint、classifier/base state 和 parent 顺序；
- CQ08 V27 train/validation split、label mapping 和 DBB 三类定义；
- `DroneTarget/BirdTarget/BalloonTarget` 三分类；Unknown 不成为类别；
- V27 L2 的 RD physical4、TR/RD 基座输出和原始 sequence logits；
- `fixed_parent_count` 的分类损失语义、train-only class weights、batch
  归约规则和 prefix 评估口径；
- seed、dataloader 顺序、epoch 数、学习率、weight decay、gradient clip、
  batch size 和 early-stopping/checkpoint 规则（由 V27a config 固定）；
- residual 的 zero-init、无 bias、三类 zero-sum、逐事件绝对上界和 padding
  中性规则；
- offline、chunked、online 使用同一 evidence/residual cell；
- L3 registry、L1 输入、Liquid V2 状态方程和 V27 baseline 文件。

V27a 首轮明确禁止：

- 重新训练或解冻 V27 Liquid V2、Fusion、TR/RD encoder、classifier；
- 把 evidence 再拼回共享 Fusion；
- 重新拟合或调整动态 L3、knownness、quality/maturity 或 Unknown gate；
- 使用 Unknown、Clutter 或 test 作为 residual 分类训练目标；
- 使用 raw frame index、MAT ordinal、sample ID、track/capture ID、路径、
  sampling mode 或其他 provenance shortcut；
- 使用双向 encoder、未来事件、最终轨迹统计或 padding；
- 首轮加入 181/64 profile 或未经 mode-readiness 的 23 维全量输入；
- 根据 validation 错误事后改变 residual bound、特征列、可靠性门槛或
  checkpoint 规则。

### 5.2 可靠性语义

当前 V18/V27 的 `valid` 语义是 `RD 是否存在`，不是“是否有可靠微多普勒
帧”。因此实现必须同时携带并区分：

```text
rd_present
micro_frame_available
reliable_frame_count
reliable_frame_fraction
profile_estimable
```

当前 train DBB event 中有 310 个没有可靠微多普勒帧，其中 157 个仍是
`valid=True` 的 RD-present/no-reliable 事件（Drone 86、Bird 71、Balloon 0），
另有 153 个 RD-missing 事件（Drone 80、Bird 72、Balloon 1）；val 中有 104
个，其中 RD-present/no-reliable 为 49 个（Drone 49、Bird 0、Balloon 0），
RD-missing 为 55 个（Drone 32、Bird 22、Balloon 1）。因此 `valid=True` 不能
被当作微多普勒可靠性。

这些事件都不产生新的 evidence update，但只有前一组可以同时标记
`rd_present=True`。实现必须保留两套事实，不能用一个 `valid` 位替代它们。

### 5.3 允许输入字段

首轮 main treatment 只读取：

- `frame_values[:, stable8_indices]`；
- `frame_feature_reliable`；
- `event_offsets`；
- 由 event offsets 计算的 frame mask 和 event mask。

stable8 的 8 个 canonical frame 列为：

```text
residual_positive_8_30mps_energy_fraction
residual_negative_30_60mps_energy_fraction
residual_positive_30_60mps_energy_fraction
residual_rms_offset_mps_over_90
residual_top4_resolution_cell_concentration
residual_sideband_snr_db_over_30
pulse_envelope_rms_clipped_0_2_over_2
pulse_envelope_modulation_snr_db_over_30
```

事件摘要对照臂使用同一 8 列的 V18 stable8 summary cache，但必须用 evidence
cache 的 `frame_feature_reliable` 重新计算 `summary_valid = reliable_count > 0`
并按事件顺序建立输入。对于有可靠帧的事件，重算值必须与 summary cache
逐值一致；summary cache 的全零行不能被解释为可靠观测。

### 5.4 不变量

- `sample_ids` 与 V27 event sample order 完全相等；
- `event_offsets` 长度为 event count + 1，单调不降，首值为 0，末值为
  frame count；
- frame mask 只描述事件内观测顺序，不能作为模型数值 shortcut；
- reliable frame 必须属于 active frame；inactive/padding frame 的值、mask、
  residual 均为零；
- Track 1010 的 raw-DAT/MAT ordinal/canonical index 差异只用于审计，不能
  进入模型输入；
- invalid/missing stable8 值严格为零，但同时保存其 validity 语义；
- 只有当前及历史已观测 frame/event 可以影响当前输出。

## 6. Residual 结构合同

两 treatment 共用下列输出约束。令 `e_t` 是当前事件的 evidence representation，
`h_t` 是 parent/event GRU 状态：

```text
u_t = parent_event_gru(e_<=t)
q_t = W u_t
z_t = q_t - mean(q_t)
residual_t = z_t * min(1, B / max(abs(z_t)))
logits_t = frozen_logits_t + residual_t
```

实现细节：

- 初始 residual 参数全零，因此 treatment 在初始化时逐值等于 Control；
- 最终 residual projection 两臂均无 bias 且全零初始化；不能只对 mechanism
  control 使用无 bias 约束；
- `B` 是预注册配置变量，默认沿用 V19 的工作上界 `3.0` 作为待审计起点，
  不是 validation 后可调旋钮；
- 每一事件 residual 的每类绝对值不超过 `B`，三类和为零，pairwise correction
  不超过 `2B`；
- 无可靠 frame 的事件不调用 evidence encoder，`parent/event` 状态保持不变，
  因而该事件的 `evidence_update` 与 `residual_increment` 必须 exact-zero；
  如果此前已有可靠证据，输出 residual 可以保持此前值，不能把“保持”误报为
  新的零证据或强制清空历史证据；首个无可靠帧事件的 residual 必须为零；
- padding 不调用任何 encoder，padding 输出按合同置零；
- residual 不修改 frozen Liquid state、classifier state 或 V27 checkpoint；
- 保存 residual 参数、输入 schema、bound、zero-sum 规则和 frozen-base hash。

`B=3.0` 只是容量/安全上界的预注册工作点。历史 V19 的结果不能证明
V27a 会改善 Bird；若要比较 bound，必须另立后续单因素实验，不能在本实验
中事后选择。

## 7. 训练设计

### 7.1 训练数据角色

首轮只使用 V27 L2 known DBB train parents 拟合 residual。Unknown 不进入
分类目标；V27a 不开放新的 open-set 训练角色，也不使用 L3 calibration。
训练/validation 的 parent 边界、class weights 和 feature normalization
必须独立记录并 hash 绑定。

stable8 normalization 在 V27a 中单独拟合：先对每个 train-known parent 的
可靠 frame 做 feature-wise median，再在 parent 等权的这些 median 上拟合
全局 median/IQR。该同一组统计量同时用于 Main 的 frame token 和 Mechanism
control 的 summary token，避免长 parent 支配尺度，也避免把 V19 的事件级
统计量误当作 frame-level contract。V19 统计量只作为审计对照，不能静默复用。
validation 只能评估，不能拟合 normalization、residual bound、特征列或
checkpoint。

### 7.2 目标与优化

主目标沿用正确的 parent-level class-balanced classification objective，
但必须保证 residual 训练实现实际调用 `fixed_parent_count` 归约；不得复用
V19 的旧 `batch_weight_sum` 语义。

首轮不加入 knownness、quality、metric learning、prototype、Mahalanobis、
energy、conformal 或 L3 loss。原因是本实验只测微多普勒证据载体/解耦机制，
不能同时改变开放集任务。

推荐训练顺序：

1. 先冻结并缓存 Control sequence logits；逐样本断言 cache logits 与
   epoch-11 基座输出一致；
2. 运行 Control 与两个 treatment 的 contract/smoke；
3. 只训练 residual/evidence branch 参数；
4. 每个 epoch 保存不可覆盖 checkpoint；固定预注册的最终 epoch 作为主要比较，
   own-best 只以既有 epoch checkpoint 的次要索引报告，不能写入可变的
   `best_model.pt` 或用 validation 结果事后重选；
5. 训练完成后在同一 validation 上比较三臂，不做 L3 校准。

正式确认至少使用三个 residual seeds（建议 42/43/44），共享同一个冻结
V27 epoch-11 base；seed 42 可先作为 smoke/full-pipeline 试运行。若只运行
单 seed，结论必须标为 exploratory，不能写成 V27a 已采纳。

## 8. 因果、padding 与 online 合同

对每个事件 `t`：

- 只读取该事件的 frame `1..K_t`，并按 evidence cache 原始观测顺序处理；
- event representation 只读取事件内当前/过去 reliable frame；不可靠 frame
  被 mask 掉且不能通过位置、数量或 sampling metadata 间接进入；
- parent aggregation 只读取 event `1..t`，不读取 `t+1..T`；
- 若当前事件没有可靠 frame，branch 不调用可学习 evidence update，输出
  exact-zero `evidence_update`/`residual_increment`；父级状态只保持，不清空
  已有历史证据；
- 若 parent 后缀为 padding，padding 不调用 frame encoder、event encoder 或
  residual head；
- chunked continuation 必须携带 evidence encoder 的显式 initial state，且
  与 offline 同步；
- 同一输入、初态、mask、offset 和 bound 下，offline/online/chunked 的
  residual 与 combined logits 必须在预注册浮点容差内一致；
- 修改未来事件/frame 不能改变此前 prefix residual/logits。

## 9. 评估指标与比较顺序

### 9.1 主指标

按 parent-final 首先比较：

- Macro-F1、balanced accuracy、accuracy；
- Drone、Bird、Balloon 的 precision/recall/F1；
- Bird→Drone、Drone→Bird 及双向错误总数；
- 与 Control 的 parent-level paired correctness、paired bootstrap 区间。

其次比较 parent-balanced eligible-prefix（最小 3 事件、排除 final）以及
逐 prefix 诊断。长轨迹不能因事件多而自动获得更大权重。

### 9.2 机制与稳定性指标

- residual absolute max、zero-sum max、pairwise max；
- 无可靠 frame 事件的 `evidence_update`/`residual_increment` exact-zero，及首个
  无可靠事件 residual 为零、后续无可靠事件仅保持既有 residual 的合同；
- Control/treatment frozen-base logits 逐值一致性；
- evidence branch 参数量、梯度范数、NaN/Inf；
- 按事件数、可靠帧数/比例、RD presence、SNR、距离、sampling mode 和
  类别分层报告；sampling mode 只用于分析，不作为模型输入；
- prefix future-perturbation、padding invariance、offline/online/chunk
  一致性。

### 9.3 解释顺序

1. 先检查三臂的 frozen logits 与 residual contract；
2. 再检查 Known DBB 分类安全与 Bird/Drone 方向；
3. 再检查低质量/无可靠帧子集，防止低质量样本被当作“修复”；
4. 最后看整体 Macro-F1 和配对区间。

V27a 不报告 Unknown rejection、knownness AUROC、L3 action coverage 或
deployment eligibility；这些属于后续新实验，不能从本实验推导。

## 10. 采纳与失败门槛

### 10.1 必须通过的硬合同

任一项失败即停止：

- frozen classifier/base state hash 完全不变；
- Control 初始化和 residual zero-init 逐值一致；
- residual zero-sum、bound、padding、无可靠帧 exact-zero 全部通过；
- frame/event/sample 对齐、offset、Track 1010 审计和可靠性语义通过；
- 无未来泄漏，offline/online/chunked 一致；
- 所有状态、logit、loss、梯度有限。

### 10.2 性能解释门槛

Mechanism control 只有在以下条件同时满足时，才可称为“解耦机制获得支持”：

- 固定主要 epoch 下 parent-final 的总正确 parent 不少于 Control；
- Bird precision、Bird recall 与 Drone recall 不下降，Drone→Bird 与 Bird→Drone
  均不增加；
- parent-balanced eligible-prefix 不出现预注册的安全退化；
- 低质量/无可靠帧子集不被错误计为 evidence 修复。

Main treatment 只有在相对 Mechanism control 提供额外信息时，才可称为“逐帧
证据有增量”：

- 在相同主要 epoch 和相同冻结 base 下，parent-final 或 eligible-prefix
  至少一个主要层级有稳定正向增量；
- Bird precision/recall/F1 与 Drone↔Bird 双向错误共同审查，不能只看 Bird
  recall；
- 增量不能由参数量、padding、事件长度、sampling mode 或 provenance
  shortcut 解释；
- parent paired bootstrap 的主要差值方向与分层结果一致，支持数不足时只
  报告探索性证据。

若只有 Bird recall 上升但 precision、双向错误或 Macro-F1 退化，结论为
“边界移动/失败”，不是成功。若 treatment 失败，不增加 residual 层数、不
调 L3 阈值、不重新训练 V27 主干；为下一个实验递增编号。

## 13. 明确没有证明什么

V27a 即使通过，也只能证明在冻结 V27 L2 基座上，某种独立微多普勒证据
residual 机制对已知 DBB 分类的相对作用。它不能证明：

- V27 L1 迁移正确或 L1 open-set 改善；
- Unknown 排序、knownness 训练或 L3 动态校准有效；
- 跨 source/跨设备泛化；
- profile 或完整 23 维 evidence 一定有益；
- V1/V2 主干谁更优；
- 可以部署。
