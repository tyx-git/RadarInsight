# V27 baseline：完整 L1–L2–L3 Liquid V2 系统基线

> 文档状态：2026-09-01  
> 范围：仅 `src-v3`；`src` 不属于本实验。  
> 身份：`V27 baseline` 是完整系统的基线规范与实现合同；`V27a` 才能用于后续单因素实验编号。

## 1. 结论与边界

V27 不是“先做完 L2 再补 L1/L3”的别名。它从一开始就必须拥有完整的 L1、L2、独立 open-set 表征/质量分支和 L3 动作合同；可以分阶段训练、校准和验证，但不能把未具备这些边界的 L2 三分类器称为 V27 baseline。

- L1：只学习 `KNOWN_TARGET_EVIDENCE` / `KNOWN_CLUTTER_EVIDENCE`，输入为已知类（Drone/Bird/Balloon/Clutter）；Unknown 不进入训练类别。
- L2：只学习 Drone/Bird/Balloon 三分类，只接收 DBB 训练父样本；Unknown 不是第四类。
- L1 与 L2 都是独立的 Liquid V2 实例、独立参数、独立 raw state、独立分类头、独立 knownness/quality 头。统一的是状态方程、wrapper、时间策略和 checkpoint 合同，不是权重或状态共享。
- knownness 与 quality/maturity 都不等同于 softmax、margin、energy、单点距离或分类 LayerNorm 终态；它们是独立任务输出，且其未校准分数不能直接触发产品动作。
- L3 是唯一可以输出 `PENDING_ABSTAIN`、`UNKNOWN_REJECTED`、Clutter 或 DBB 子类的层。动态校准尚未拟合时，L3 必须 fail-closed 为 Pending，绝不回退为固定 softmax 或单距离阈值。

当前 V27 的实现目标是先建立上述可训练、可审计的系统骨架与分类训练路径。它不是正式训练结果，也不具备部署资格。

## 2. Liquid V2 主干合同

V27 唯一产品主干是自研 Liquid V2：

\[
n_{t-1}=\operatorname{LN}_{\mathrm{compute}}(r_{t-1})
\]

\[
(c_t,g_t)=F(x_t,n_{t-1})
\]

\[
m_t=g_t\odot c_t+(1-g_t)\odot r_{t-1}
\]

\[
r_t=(1-\alpha_t)\odot r_{t-1}+\alpha_t\odot m_t
\]

其中 `r_t` 是持续保存的 raw memory，绝不在递归更新后写回 LayerNorm 结果。`LN_compute` 仅供 candidate/gate 稳定计算；分类头使用自己的 `LN_classifier(r_t)`；knownness 从完整 raw trajectory 分叉；quality/maturity 也有独立头。三者不能共享同一个 LayerNorm 或让后两者的输出回流到主干、分类输入或彼此。

需要显式区分三类轨迹量：

- `candidate_innovation = c_t - r_(t-1)`
- `mixed_memory_innovation = m_t - r_(t-1)`
- `actual_update = r_t - r_(t-1)`

L1/L2 的 active time policy 固定为 `bounded_observation`。`density_weighted`、`strict_skip`、`skip` 与 `floor` 作为实现能力和后续单因素变量保留，但不得在 V27 baseline 中暗中启用。padding 永不调用 cell；offline、chunked、online 必须通过同一 cell 和同一 time-policy contract。

官方 CfC 仅作为工程组织参考：cell/wrapper/time-policy 分层、显式 initial state、sequence/final state 同时返回、padding 不递归、offline/online 共用 cell、hash 绑定。官方状态方程、mixed memory、wiring 和第二套产品主干均不迁移。

## 3. 分层特征与数据角色

| 层/职责 | V27 baseline 的固定输入与边界 | 历史来源 |
|---|---|---|
| L1 分类 | TR、RD spatial、`rd_quality`、确定性 dt facts、`causal_prefix_course_circular_incoherence` 的 value/valid/support | V21e 的正向因果圆形离散度 |
| L2 分类 | TR、RD spatial、`rd_quality`、确定性 dt facts、RD physical4、stable8 micro-Doppler | V18 stable8 特征合同 |
| knownness | 完整 `r_1:T`、三类 innovation、gate/alpha/tau、dt/zero ordinal、RD/微多普勒 validity、质量事实与轨迹成熟度 | V26k 反例后形成的任务匹配表征要求 |
| quality/maturity | 可审计的有效事件数、RD/微多普勒可用性、dt 语义、缺失模式和其他确定性质量事实 | 不使用 Unknown、错误分类或低 posterior 伪造监督 |
| L3 | 已校准的 L1/L2 knownness、quality、conformal set、路由/子类冲突和 eligibility | V26 系统协议仅作参考 |

`rd_quality`、dt reason/validity、event count、RD/微多普勒 validity 等确定性事实允许进入分类与旁路表征，以提升缺失鲁棒性；但 learned quality head 的输出禁止回流。L1 runtime normalization 只能来自 known-only train（DBB + Clutter，排除 Unknown）；L2 runtime normalization 只能来自 DBB train（Drone/Bird/Balloon，排除 Clutter/Unknown）。历史五类统计仅是 V18 feature-generation provenance，不能作为 V27 runtime 输入。

Unknown 不进入 L1/L2 分类 loss、runtime normalization、early stopping 或分类 checkpoint selection；但在分类基座冻结后，可以进入隔离的 `representation_fit` 作为独立 knownness 分支的负例，进入 `representation_development` 做头部选择/排序诊断，并进入独立 `calibration` pool 拟合 L3。quality head 对 Unknown 只使用确定性质量/成熟度事实，不把 Unknown 标签伪装成质量监督。test、final audit 与跨源验证仍封存；V27 baseline 当前不执行 OOF/跨源结论。

## 4. Open-set 与 L3 动作合同

V26k 已表明，把 Mahalanobis 施加到仅为闭集相对分类优化、且经历递归 LayerNorm 的 parent-final 状态上，会同时损伤已知召回并接受大量 target-route Unknown。因此 V27 禁止单一距离阈值直接 gate；这不等于取消硬动作边界。

L3 只消费经过独立 calibration pool 拟合后的布尔接受/集合语义，而不直接比较未登记的 raw score。动作顺序固定为：

1. 有效事件、RD/微多普勒质量、dt 语义或成熟度不足：`PENDING_ABSTAIN / LOW_QUALITY_OR_IMMATURE`。
2. calibration 未拟合：`PENDING_ABSTAIN / CALIBRATION_NOT_FITTED`。
3. L1 target/clutter 冲突：`PENDING_ABSTAIN / L1_ROUTE_CONFLICT`，绝不退回 Clutter。
4. 质量充分但 L1 或 L2 knownness 不足，或其 conformal set 为空：`UNKNOWN_REJECTED / OOD_NONCONFORMING`。
5. L1 可靠接受 Clutter：`ClutterTarget / L1_CLUTTER_ACCEPTED`。
6. L1 可靠接受 target，且 L2 只有一个可靠 DBB 类：Drone/Bird/Balloon。
7. L2 DBB 子类证据冲突：记录 `KNOWN_CLASS_AMBIGUOUS`；流式未成熟时 Pending，终态质量充分时 Unknown；绝不回退为 Clutter。

固定 softmax 阈值只允许作为未来效率 comparator，不能成为 V27 正式 open-set 机制。32 维 projection、多原型、kNN、Mahalanobis、energy、margin 组合以及质量监督的具体形式均为可消融候选，不是已证实答案。

## 5. 训练与校准顺序

1. 分别训练 L1 与 L2 的 known-class classification，使用 train-only class weights 和 `fixed_parent_count` 归约；不允许按 batch 中类别组成重新归一化。
2. 冻结每个通过分类安全检查的主干/分类头，单独训练 knownness projection/评分器及 quality head。quality 标签必须来自明确、可审计的观测质量或成熟度定义。
3. 先报告 known recall、eligible-prefix、安全弱类指标和 knownness 排序；不能把低质量 Pending 计作 Unknown 成功。
4. 仅在新任务实测出有害梯度冲突后，才考虑低学习率局部联合微调、交替优化或 PCGrad。V25 的旧 L1 冲突不是新任务必然冲突的证据。
5. 用完全独立的 calibration pool 拟合温度、conformal 集、质量条件和 L3 动作边界；它不参与训练、normalization、early stopping 或 final audit。

每个 checkpoint 必须绑定 task/layer、state equation、time policy、feature/normalization/split registry、loss reduction、class weights、实现 hash 和 continuation schema。V1→V2、L1→L2、control→treatment 或不匹配校准 registry 均严格拒绝加载。

## 6. 当前实现完成标准

截至 2026-09-02，V27 baseline 的代码链路、独立 head 训练、动态 calibration、development replay 和 audit 均已执行。当前实现合同通过，但 development replay 的 KnownTarget route recall 尚未达到产品安全线，因此仍不得宣称部署就绪。

V27 baseline 的代码完成不等于实验晋级。实现完成至少要求：

- L1/L2 都可独立前向、训练分类、返回 raw trace、knownness projection/logit 与 quality logit。
- L1 course feature 的 value/valid/support 与 V21e cache 严格对齐；L2 固定 RD physical4 + stable8。
- L1/L2 的 raw state、参数、classifier norm、knownness head、quality head 都不共享；修改后两者参数不得改变分类 logits。
- L3 对未拟合 registry fail-closed，并覆盖 Pending、Unknown、Clutter、唯一 DBB 类、L1 冲突和 DBB 冲突的 reason code。
- config、路径、cache、normalization、split、实现和 action schema 都有 canonical hash；错误路径、错误 hash、错误 task checkpoint 均 fail-closed。
- contract smoke 覆盖 padding、empty sequence、bounded-observation、initial state、trace、L1/L2 隔离和 L3 逻辑；本轮分类/head 训练、动态 calibration、development replay 和 audit 已执行，OOF、跨源、test 和部署仍未执行或未获资格。

本轮实际结果：calibration pool 的 KnownTarget route recall 为 `210/220=0.9545`、Clutter recall 为 `8/9=0.8889`，development replay 的 KnownTarget route recall 为 `424/451=0.9401`、Clutter recall 为 `1.0000`，Unknown 的 OOD nonconforming rejection 为 `13/38=0.3421`。因此 calibration 安全线通过，development KnownTarget safety floor 未通过，`deployment_eligible=false`。不得使用 development replay 反向改写 calibration registry。

## 7. 明确禁止的做法

- 把 Unknown 加为 L1/L2 常规类别，或让 Unknown 进入 runtime normalization。
- 将 max-softmax、classification margin、LayerNorm 终态或单一 Mahalanobis 距离直接当 knownness gate。
- 让 learned quality score 回流到分类器或用低 quality 伪装 Unknown 拒识成功。
- 让 L1/L2 共享 recurrent state、权重或错误加载 checkpoint。
- 在 V27 baseline 中默认启用 `density_weighted`、`strict_skip` 或未校准的固定阈值。
- 将当前结构/烟雾测试通过写成 L2 优于 V1、open-set 有效或可部署的实验结论。

## 8. 结论

V27 的可证伪核心是：以 V18 stable8 的 L2 表征锚点、V21e 的 L1 因果圆形离散度、自研 raw-memory Liquid V2、独立 classification/knownness/quality 头和动态校准 L3，建立一个不把低质量、类内歧义、错误已知和真正 OOD 混为同一拒识结果的完整三层系统。

优先级固定为：任务匹配表征 → knownness 排序与 known-recall 安全 → 独立 calibration → L3 硬动作。任何距离公式、投影维度、原型数或联合优化方案都必须在该顺序下接受消融和证伪。
